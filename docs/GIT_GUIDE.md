# Git и GitHub для новичка — минимальный гайд

Git нужен в вайб-кодинге не «потом», а с первого дня. Агент может сломать
проект одним промптом. Без коммитов вы не откатитесь.

В платформе курса вместо настоящего Git работают **снапшоты** (кнопка
«Снапшот» в Monaco). Это упрощённый локальный Git для обучения. После
курса переходите на настоящий Git и GitHub — этот гайд для второго шага.

## Первая настройка (один раз)

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

## Минимум команд

```bash
git init                           # начать новый репозиторий
git status                         # что изменилось
git add .                          # подготовить всё к коммиту
git commit -m "feat: add form"     # зафиксировать
git log --oneline                  # история
git diff                           # что нового с момента коммита
git restore index.html             # откатить файл
git checkout -b feature/dark-theme # новая ветка
git push origin feature/dark-theme # отправить на GitHub
```

## Conventional Commits (рекомендуется)

Делайте сообщения по схеме `тип: что сделано`:

- `feat:` — новая функциональность
- `fix:` — починка бага
- `docs:` — изменения в документации
- `refactor:` — изменения без новой логики
- `chore:` — служебные (зависимости, конфиги)

## GitHub за 5 шагов

1. Зарегистрироваться на [github.com](https://github.com).
2. Создать новый репозиторий (без README — он уже в вашей папке).
3. Скопировать предложенные команды `git remote add origin ...` и `git push -u origin main`.
4. Создать ветку `feature/...` для каждой новой задачи.
5. После завершения — открыть Pull Request, проверить diff, merge в `main`.

## Pull Request — место контроля агента

PR — это «проверочный пост» между агентом и `main`. Никогда не сливайте в
`main` без PR. В PR видно: список файлов, diff, комментарии. Вы смотрите
diff, артефакты и решаете: принять, попросить правки или отклонить.

Шаблон PR-описания лежит в `docs/templates/PULL_REQUEST_TEMPLATE.md`.

## Когда ИИ сломал проект — откатываемся

```bash
git status      # что изменилось
git diff        # как именно
git restore .   # отменить все правки до последнего коммита
```

Если правки уже закоммичены:

```bash
git log --oneline           # найти хеш предыдущего коммита
git revert <hash>           # создать обратный коммит (безопаснее всего)
```

## Опасные команды (не используйте без понимания)

- `git reset --hard <hash>` — перепишет историю, можно потерять работу.
- `git push --force` — затрёт чужие изменения.
- `git clean -fd` — удалит неотслеживаемые файлы навсегда.

## .gitignore — что нельзя коммитить

Никогда не пускайте в репозиторий:

- `.env` с реальными ключами
- `node_modules/`
- системные `.DS_Store`, `Thumbs.db`
- собственные секреты, пароли, токены

Шаблон лежит в `docs/templates/.gitignore.example`.
