# Centras CodeAI — аудит песочницы/IDE и план упрощения

_Подготовлено как senior frontend-инженером и тренером по вайб-кодингу. Это
план (без правок кода) — по правилу из `CLAUDE.md` сначала согласование, потом
изменения. Дальше по тексту «ученик» = русскоязычный новичок без бэкграунда._

---

## 0. Короткое резюме (TL;DR)

Платформа сделана сильно: чистый стек (React 19 + Vite + TS + Zustand + Monaco +
Supabase), честная изоляция песочницы (`iframe sandbox="allow-scripts"` + мост
консоли через `postMessage`), трёхслойный грейдинг (статика → функциональные
тесты в iframe → рубрика LLM) и демо-режим без бэкенда. Это хороший фундамент.

Главная проблема — **не нехватка функций, а их переизбыток и дублирование**.
В продукте фактически живут **два параллельных движка одного и того же цикла
вайб-кодинга**:

- **Тур** (`/tour`) — педагогически сильнее: строго пошаговый, есть роли, живой
  разбор диффа (`DiffAuditor`), «Кнопка Паники» (Loop Breaker). Но это
  отдельный Zustand-стор, свои типы, своя песочница.
- **Практика** (`/practice`) — мощнее по возможностям (реальный грейдинг,
  деплой, миссии), но перегружена «декорациями под взрослую IDE» и до **четырёх
  наложенных полос шагов** на одном экране.

Второе противоречие — **обещание против реальности**: курс учит «ты не пишешь
код руками, ты дирижируешь агентом», а миссии 3–4 недели заставляют новичка
вручную писать `addEventListener`, `escapeHtml`, регэкспы. Встроенный «агент»
(`agentInstructions`) задействован ровно в **1 миссии из 12**.

Решение — собрать **единый пошаговый изолированный режим** (Guided Sandbox):
один шаг за раз, «Дальше» заблокировано до прохождения, вся pro-декорация скрыта
по умолчанию (прогрессивное раскрытие), а ИИ-агент **реально пишет код по
кнопке** — ученик читает дифф и жмёт «Принять / Отклонить», как в настоящем
Antigravity.

## 1. Архитектура как есть

### 1.1 Стек и маршруты

| Слой | Технология |
|------|-----------|
| UI | React 19, react-router-dom 7, Monaco (`@monaco-editor/react`), lucide-react |
| Состояние | Zustand (тур), React state + сервисы (остальное) |
| Бэкенд | Supabase (auth, `courses`/`course_modules`/`module_blocks`, `progress`, `submissions`, `tour_events`) + edge-функция `ai-gateway` |
| Демо-режим | localStorage-фолбэк + детерминированные моки в `aiGateway.ts` |

Маршруты (`App.tsx`): `/` (Hero + таймлайн), `/tour`, `/preview/:id`,
`/program` (**сирота — дубль главной, на него нет ни одной ссылки**), `/slides`,
`/practice`, `/resources`, `/auth`, `/teacher`.

### 1.2 Песочница и изоляция — это сделано правильно

`lib/consoleBridge.ts → buildSandboxDoc()` собирает `srcDoc` для
`iframe sandbox="allow-scripts"`: внутрь инжектируется shim, который
перехватывает `console.*`, `window.onerror`, `unhandledrejection` и шлёт их в
родителя через `postMessage` с меткой `bridgeId`. Тот же канал гоняет
функциональные тесты (`api.$/click/text/exists/type`) внутри песочницы.
Платформенный `localStorage` коду ученика недоступен — соответствует запрету из
`CLAUDE.md`. **Этот механизм трогать не нужно, он надёжный.**

### 1.3 Грейдинг (3 слоя) — тоже хорошо

`lib/grading.ts` + `lib/aiGateway.ts`: статические проверки (DOMParser,
`new Function` на синтаксис) → функциональные тесты в iframe → рубрика LLM через
`ai-gateway`. Формула `0.5*рубрика + 0.4*функц + 0.1*статика`. Есть честный
демо-симулятор (`mockGrade`, `mockLint`, `mockExplain`) — платформа работает без
облака. Это сильная сторона, её сохраняем.

## 2. Стек пользователя и user stories

### 2.1 Персона

**Марат, 29, не-программист.** Менеджер/маркетолог/предприниматель. Хочет
собрать свой MVP с помощью ИИ. Терминала боится, слова «дифф», «коммит»,
«регэксп» для него шум. Сидит с ноутбука в Chrome. Мотивация высокая первые
2 недели, дальше выгорает, если «непонятно, что делать дальше».

**Стек, который ему реально нужен в курсе:** браузер → онбординг-тур → слайды
(теория) → пошаговая практика в песочнице → внешний инструмент (Antigravity/Gemini)
→ артефакт недели → квиз. Куратор отдельно смотрит сдачи.

### 2.2 User stories (скомпилированы по факту кода)

1. _Как новичок_, я хочу за 10 минут «потрогать» весь цикл вайб-кодинга, чтобы
   поверить, что у меня получится. → **есть** (`/tour`), но перегружен жаргоном.
2. _Как новичок_, я хочу на каждом занятии видеть **один понятный следующий шаг**,
   а не 4 панели сразу. → **не выполнено** (см. §3).
3. _Как новичок_, я хочу, чтобы **ИИ написал код, а я только проверил**, потому
   что меня этому и обещали учить. → **не выполнено** (миссии заставляют писать
   руками; агент подключён в 1 миссии).
4. _Как новичок_, я хочу понятную обратную связь по промпту («вот это слабо,
   потому что…»), а не «поле не должно быть пустым». → **не выполнено** (фейковая
   проверка, хотя реальный `lintPrompt` уже написан в `aiGateway.ts`!).
5. _Как новичок_, я хочу не бояться сломать — кнопку «вернуть как было». → частично
   (есть снапшоты, но спрятаны за «git-граф» и жаргоном «commit/HEAD»).
6. _Как новичок_, я хочу понимать незнакомые слова прямо на месте. → **нет
   глоссария / подсказок**.
7. _Как куратор_, я хочу видеть, кто застрял и на каком шаге. → частично (есть
   `TeacherDashboard`, но смешивает реальные сдачи и фейковые «квоты/Docker»).

## 3. Что лишнее и дублируется (карта избыточности)

Это прямой ответ на «лишние кнопки и где-то непонятно».

### 3.1 До 4 наложенных «полос шагов» на `/practice`

На одном экране сверху вниз идут:

1. `practice-week-nav` — кнопки недель (`App.tsx:307`)
2. `practice-path-strip` — **те же недели** другим виджетом (`App.tsx:329`)

Две первые полосы — буквально дубль навигации по неделям. Ученик не понимает,
по какой кликать.

### 3.2 «Декорации под взрослую IDE» (фейк, грузит новичка)

- **Фейковые пиллы RAM/CPU/деплои/время** — «Системные ограничения песочницы»
  (`CodeEditor.tsx:573`). Это административная выдумка, никакого Docker нет.
- **Фейковый git-граф + ветка `main`** (`CodeEditor.tsx:716`, топбар `:679`).
- **`AICoachPanel` «Запустить план»** — поддельная анимация pending→done на
  таймере 650 мс, ничего не делает (`AICoachPanel.tsx:260`).
- **Ответы ИИ-коуча шаблонные** (`buildCoachReply`), но выглядят как живой ИИ —
  новичок ждёт реальной помощи.
- **`TeacherDashboard`** транслирует «Docker/RAM/CPU» в продукт как настоящие.

### 3.3 Одно и то же действие в 2–4 местах

| Действие | Где дублируется |
|----------|-----------------|
| Помощь ИИ / чат | `AICoachPanel` + чат тура + грейдинг в `PromptBuilder` |
| Сборка промпта | `PromptBuilder` + шаг тура + шпаргалка в `AICoachPanel` + «копировать шаг» в `App.tsx:442` |
| «Проверить/сдать» | `CodeEditor` (2 кнопки) + `PromptBuilder` + тур + квиз — 4 формулировки |

| Порог зачёта 80 | хардкод в `Quiz.tsx:6`, `PromptBuilder.tsx:144`, `CodeEditor` |

### 3.4 Объявлено в типах, но не используется

- `MissionType`: `diff-audit`, `bug-reproduce`, `loop-breaker`, `local-storage` — **0 миссий**.

## 5. Чего не хватает (gaps)

1. **Плавного входа в код.** Между «ИИ пишет код» (теория) и «напиши `addEventListener`
   сам» (миссия) — обрыв. Нужен либо встроенный агент, который пишет, либо
   микрошаги «прочитай → измени одну строку».
2. **Реальной проверки качества промпта.** `lintPrompt()` уже есть в `aiGateway.ts`,
   но миссии 1–2 недели его не зовут — проверяют лишь «поле не пустое».
3. **Практики по CSS** — целый `target: 'css'` простаивает (визуальный успех очень
   мотивирует новичка).
4. **Реальной отладки** — «Stop-Snapshot-Reproduce-Isolate» учат словами, миссии
   `bug-reproduce`/`loop-breaker` не сделаны (хотя механика «Кнопки Паники» уже
   написана в туре).
5. **Глоссария / всплывающих определений.**
6. **Индикатора «сохранено» и автосохранения черновиков** (промпт/код теряются
   при перезагрузке).
7. **Единого якоря «что делать прямо сейчас».**
8. **Контекстных ресурсов** (поля под это есть, но пустые).

## 7. Решение — единый «Пошаговый изолированный режим» (ядро ноу-хау)

Идея: оставить мощь Практики, забрать педагогику Тура, выкинуть декор.

### 7.1 Принципы

1. **Один шаг за раз.** На экране — текущий шаг, его инструкция, его действие.
   Остальное свёрнуто (прогрессивное раскрытие — подтверждено как best practice).
2. **Изоляция шага.** Кнопка «Дальше» неактивна, пока проверки шага не зелёные.
   (Логика уже есть: `currentStepPassed` в `PracticeMissionRunner.tsx:44`.)
3. **Агент пишет код — ученик проверяет.** Кнопка «Пусть агент сделает шаг» →
   `generateDiff()` (уже есть в `aiGateway.ts`) → показываем дифф в `DiffAuditor`
   (уже есть в туре) → «Принять/Отклонить». Это и есть вайб-кодинг и снимает
   противоречие из §0. Ученик при желании может писать сам (режим «Сам»).
4. **Pro-IDE по требованию.** RAM/CPU/git-граф/ветка `main`/Agent Manager — под
   тумблер «Режим эксперта» (по умолчанию выключен). Новичок видит: файлы → редактор
   → превью → «что дальше».
5. **Человеческий язык + глоссарий.** Жаргон заменяем или снабжаем всплывающей
   подсказкой-определением.

### 7.2 Как меняется экран `/practice` (до/после)

- **До:** 4–5 полос навигации + баннер квот + git-граф + 6 иконочных кнопок в
  редакторе + 2 кнопки «проверить» + сайдбар коуча.
- **После:** 1 полоса прогресса недели → карточка «Шаг N: что делаем» с одной
  главной кнопкой → редактор+превью → одна кнопка «Проверить шаг» → когда зелено,
  «Дальше». Всё «взрослое» — за «Режимом эксперта».

### 7.3 Архитектурный вопрос (выношу на согласование)

Сильнее всего помогает **слияние** движков Тура и Практики в один компонент
шагов. Но это аккуратно затрагивает типы `PracticeMission/MissionStep`
(правило `CLAUDE.md` — высокая осторожность, отдельный план + ревью). Поэтому в
вопросах ниже спрошу глубину переделки.

## 9. План внедрения (фазами, субагентами, с откатом)

Реализацию веду субагентами (как просили). Каждая фаза: **план → правка одним
субагентом → проверка (`npm run build` + `npm run lint`) → ревью отдельным
субагентом → ваш просмотр**. Перед каждой фазой — git-снапшот для отката.

- **Фаза 0 — быстрые победы (низкий риск).** Баги §6 + централизовать порог +
  `alert()` → inline. Не трогает типы. _1 субагент._
- **Фаза 1 — расхламление IDE (прогрессивное раскрытие).** Убрать дубль-полосу
  недель, спрятать квоты/git-граф/Agent-театр за «Режим эксперта», свести полосы
  шагов к одной. Только UI/CSS. _1 субагент._
- **Фаза 2 — единый пошаговый режим + агент пишет код.** Перенос `DiffAuditor` и
  «Кнопки Паники» в Практику, подключение `agentInstructions`, изоляция шага.
  Касается `PracticeMission` — _субагент + обязательный ревью-субагент._
- **Фаза 3 — контент и понятность.** Глоссарий, реальный `lintPrompt`, новые
  миссии (CSS, diff-audit), контекстные ресурсы, смягчение жаргона. _Контент-субагент._

**Риски и контроль:** не удаляю слайды/практики/квизы из `courseData.ts`; типы
меняю только в Фазе 2 с ревью; после каждой фазы — сборка и линт; демо-режим
обязан продолжать работать без Supabase.

## 10. Открытые решения для согласования
