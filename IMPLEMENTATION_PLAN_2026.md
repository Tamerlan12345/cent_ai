# Centras CodeAI — детальный план реализации

_Версия плана. Код не трогаем, пока нет вашего «ок» (правило `CLAUDE.md`).
Решения, которые вы выбрали:_

1. **Глубина:** объединить Тур и Практику в единый движок (Guided Sandbox).
2. **Агент пишет код:** да, но **как опция** — ученик может писать сам.
3. **Старт:** сначала этот детальный план фаз.

---

## 0. Инварианты (соблюдаются во всех фазах)

- **Без новых npm-зависимостей.** Всё уже есть: `zustand` (стор настроек),
  Monaco, `DiffAuditor`, `Spotlight`, `consoleBridge`, `grading`, `aiGateway`.
- **Контент не удаляем.** Слайды/практики/квизы в `courseData.ts` не трогаем на
  удаление (правило `CLAUDE.md`). Только добавляем/правим тексты по согласованию.
- **Типы — только аддитивно.** Новые поля делаем `optional`, чтобы существующий
  `courseData.ts` оставался валидным. `Slide`/`PracticeTask` структурно не ломаем.
- **Демо-режим обязан работать** без Supabase (фолбэки в `aiGateway.ts`).
- **Минимальный diff, один шаг — одно действие.** После каждой фазы:
  `npm run build` + `npm run lint` + ревью-субагент + ваш просмотр.
- **Откат:** перед каждой фазой — git-снапшот (`git switch -c phaseN`/commit).
  Любую фазу можно отменить `git revert`, ничего не ломая в соседних.
- **Каждую фазу делает отдельный субагент** (как просили), плюс независимый
  субагент-ревьюер для фаз 2–3.

## 1. Целевая архитектура единого движка

Сейчас: два независимых движка одного цикла —
`tourStore`+`TourPage` (FSM) и `PracticeMissionRunner`+`CodeEditor` (миссии).
Цель: **один движок шагов**, который оба сценария используют через адаптеры.

```
            ┌─────────────── один UI ───────────────┐
courseData → missionToScenario ─┐                    │
                                 ├──► GuidedScenario ─► <GuidedSandbox/>
tourTemplates → tourToScenario ─┘                    │   (один шаг за раз,
                                                      │    «Дальше» заблокирован,
                                                      │    опц. «агент пишет код»,
                                                      │    Режим эксперта)
                         общие: consoleBridge · grading · aiGateway · DiffAuditor
```

**Почему через адаптеры, а не переписывание типов:** `PracticeMission` и
`TourTemplate` остаются как есть; мы вводим нормализованную модель
`GuidedScenario` и две функции-адаптера. Это даёт единый UI/логику при
минимальном касании типов (правило осторожности `CLAUDE.md`).

**Новая модель (черновик, `src/lib/guided/guidedTypes.ts`):**

- `GuidedScenario { id; source: 'mission'|'tour'; title; intro; artifact; steps: GuidedStep[]; checks: GuidedCheck[]; starter: SandboxFiles; successCriteria: string[]; rubric? }`
- `GuidedStep { id; title; instruction; target: 'html'|'css'|'js'|'prompt'; checkIds; hints; doneText; agentPatch?: AgentPatch }`
- `AgentPatch { html?; css?; js?; explanation }` — заготовка для опции «агент
  пишет код» в демо-режиме (когда живой `generateDiff` недоступен).
- `GuidedCheck` — обёртка над `MissionCheck` + типы из тура.

Существующий `DiffAuditor`, `Spotlight`, `promptLinter`, `guardrails`
переиспользуются движком напрямую.

## 4. Фаза 2 — единый Guided Sandbox + опция «агент пишет код» (ядро)

**Цель:** один движок шагов для Практики и Тура; один шаг за раз; «Дальше»
заблокировано до зелёных проверок; кнопка «Пусть агент напишет» (опционально) →
дифф → Принять/Отклонить. **Исполнитель:** субагент C (build) + субагент D
(review, обязательно). **Это единственная фаза, которая трогает типы.**

### 4.1 Подшаги

| # | Подшаг | Файлы (новые/правка) |
|---|--------|----------------------|
| 2a | Нормализованная модель + адаптеры | **new** `lib/guided/guidedTypes.ts`, `lib/guided/adapters.ts` |
| 2b | Аддитивные поля типов | `types.ts`: `MissionStep.agentPatch?`, `PracticeMission.bugScenario?` (всё optional) |
| 2c | Компонент-движок | **new** `components/guided/GuidedSandbox.tsx` (+ `.css`) |
| 2d | Практика → движок | `PracticeMissionRunner.tsx` рендерит `GuidedSandbox` через `missionToScenario`; старый `CodeEditor` остаётся как «expert-редактор» внутри |
| 2e | Тур → движок | `TourPage.tsx` подаёт `tourTemplate` через `tourToScenario`; `tourStore` оставляем для аналитики воронки (`trackTourEvent`) |

### 4.2 Что переиспользуем (не пишем заново)

- Изоляция и тесты: `consoleBridge.buildSandboxDoc/runFunctionalTests` (`:24/:147`).
- Грейдинг: `grading.runStaticChecks` (`:40`), `aiGateway.gradeSubmission` (`:303`).
- Дифф-ревью: `DiffAuditor.tsx` (Принять/Отклонить) — переносим в Практику.
- Генерация кода: `aiGateway.generateDiff` (`:259`); демо-фолбэк → `step.agentPatch`.
- Подсказки: прогрессивные уровни уже в `PracticeMissionRunner.tsx:185`.
- Блокировка шага: `currentStepPassed` уже в `PracticeMissionRunner.tsx:44`.

### 4.3 Поведение опции «агент пишет код» (по вашему выбору — опционально)

- Кнопка «✍️ Пусть агент сделает шаг» рядом с редактором.
- Живой режим: `generateDiff()` → `guardrails.validateGeneratedJs` → `DiffAuditor`.
- Демо-режим: берём `step.agentPatch` (заготовку) → тот же `DiffAuditor`.
- Ученик жмёт **Принять** (код применяется, делается снапшот) или **Отклонить**.
- Ученик в любой момент может печатать сам — шаг засчитывается по `checks`,
  кем бы код ни был написан. (Это и есть «опция».)

### 4.4 Риски и их снятие

- **Главный риск — типы.** Снимаем: новые поля `optional`; `courseData.ts` не
  меняется; адаптер подставляет дефолты. Обязательный ревью-субагент D проверяет
  `tsc -b` без ошибок и что все 12 миссий и 3 тур-шаблона маппятся.
- **Риск регрессии грейдинга.** Снимаем: логику проверок не трогаем, только
  переносим вызовы; прогон существующих функциональных тестов миссий M3 (клик
  монеты, добавление привычки) до/после — поведение идентично.
- **Риск «двойного кода»** во время миграции. Снимаем: старые компоненты живут
  до подтверждения, переключение через адаптер; удаление мёртвого кода — отдельным
  коммитом после верификации.
**Откат:** фаза в отдельной ветке; `git revert` подменяет рендер обратно на
старый `PracticeMissionRunner`/`TourPage`.
**Проверка (ручная, по CLAUDE.md):** `/practice?week=3` — пройти coin-clicker
двумя способами (сам печатаю / агент пишет → Принять); убедиться, что «Дальше»
открывается только на зелёных; `/tour` — пройти весь сценарий на том же движке;
`build`+`lint`+`tsc`.

вашим «ок» между фазами. Низкий риск растёт постепенно; ядро (фаза 2) идёт уже на
расчищенном поле и с ревью.

**Жду вашего «ок» на старт Фазы 0** (или скажите, если хотите изменить порядок/состав).
